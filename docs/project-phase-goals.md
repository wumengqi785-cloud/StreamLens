# StreamLens 项目阶段性目标

## 项目总目标

StreamLens 是一个基于 C++ 的轻量级视频流转发、监控与链路诊断工具，面向设备端和边缘网关场景。

核心目标：

- 接收 RTSP/RTP 视频流
- 分析视频链路状态
- 统计网络和媒体指标
- 原样转发视频流
- 检测异常并自动恢复
- 形成可在 GitHub 长期维护的开源项目

## 阶段一：工程基础

### 目标

建立稳定、清晰、可扩展的 C++ 工程基础。

### 主要任务

- 使用 CMake 管理项目
- 固定 C++17 或更高版本标准
- 建立 `src`、`include`、`tests`、`docs` 目录
- 配置基础编译警告
- 配置 CTest 测试框架
- 建立 README 和开发文档
- 确认 Windows 编写、Beyond Compare 同步、WSL 构建流程

### 完成标准

- 工程可以在 WSL 中配置和编译
- 主程序可以正常运行
- 测试可以被 CTest 发现并执行
- 源代码目录和构建目录分离

## 阶段二：两周考核版 MVP

### 目标

完成一个可以演示、验证和解释的最小可用版本。

### 主要任务

- 实现 UDP 数据接收
- 统计接收包数量和字节数
- 实现基础 RTP Header 解析
- 检测 Sequence Number 跳变
- 统计丢包数量和丢包率
- 实现基础视频流转发
- 输出周期性运行状态
- 增加命令行参数
- 增加错误处理和优雅退出

### 预期命令

```bash
streamlens \
  --input udp://127.0.0.1:5000 \
  --output udp://127.0.0.1:9000 \
  --stats 1
```

### 完成标准

- 可以接收 UDP/RTP 数据
- 可以原样转发数据
- 可以统计包数、字节数和丢包率
- 可以通过 Ctrl+C 安全退出
- 连续运行 30 分钟不崩溃
- 有可重复的本地测试方法

## 阶段三：RTSP 流接入和本地验证

### 目标

使用本地工具模拟真实视频链路，让 StreamLens 处理实际视频流。

### 主要任务

- 使用 MediaMTX 提供本地 RTSP 服务
- 使用 FFmpeg 推送本地视频文件
- 接入 RTSP 输入
- 识别 H.264/H.265 基础信息
- 输出帧率和码率
- 使用 FFplay 或 VLC 播放转发结果
- 编写正常收流测试脚本

### 完成标准

- FFmpeg 可以向 MediaMTX 推流
- StreamLens 可以连接 RTSP 地址
- 转发后的输出可以正常播放
- 统计信息能够持续更新
- README 中包含完整演示步骤

## 阶段四：稳定性和异常恢复

### 目标

让程序具备真实设备端视频链路所需的基本稳定性。

### 主要任务

- 增加连接超时
- 增加断流检测
- 增加自动重连
- 增加网络抖动统计
- 增加缓冲队列容量限制
- 增加线程停止和资源回收逻辑
- 增加异常日志
- 使用 Linux `tc/netem` 模拟丢包、延迟和抖动

### 完成标准

- 推流停止后可以检测到断流
- 推流恢复后可以自动重连
- 模拟丢包时统计数据符合预期
- 长时间运行没有明显内存增长
- 异常退出时不会留下无法回收的线程或资源

## 阶段五：可维护性和开源发布

### 目标

把项目从个人练习项目整理成可以被其他人使用和贡献的开源项目。

### 主要任务

- 完善 README
- 增加架构图和数据流说明
- 增加配置示例
- 增加单元测试和集成测试
- 增加 GitHub Actions
- 增加代码格式检查
- 增加静态分析
- 增加开源许可证
- 编写贡献指南
- 发布第一个版本标签

### 完成标准

- 新用户可以按照 README 编译和运行
- CI 可以自动完成构建和测试
- 关键模块具有测试覆盖
- 项目结构和模块职责清晰
- 能够发布 GitHub Release

## 阶段六：长期扩展

### 功能方向

- H.264/H.265 NALU 解析
- 关键帧检测
- 环形缓冲区
- 多路视频流管理
- JSON 状态接口
- HTTP/WebSocket 监控接口
- Prometheus metrics
- SRT 支持
- WebRTC 输出
- 插件化输入输出模块

### 嵌入式方向

- ARM Linux 交叉编译
- 树莓派、RK3568 或 Jetson 验证
- 硬件编解码接口适配
- 零拷贝优化
- CPU 和内存占用优化
- 设备端守护进程
- 交叉编译和安装脚本

## 阶段优先级

```text
工程基础
   ↓
UDP/RTP 接收与转发
   ↓
统计与丢包检测
   ↓
RTSP 接入与实际视频验证
   ↓
断流重连和稳定性
   ↓
测试、文档和开源发布
   ↓
嵌入式和高级协议扩展
```

## 当前建议

当前优先完成阶段一，然后进入阶段二。第一版不应同时追求 RTSP、WebRTC、硬件编解码和嵌入式移植。

每完成一个阶段，都应该保留一个可以编译、运行和演示的版本，并同步更新 README、测试记录和文档。
